From ANT to MAXI

The ant brain language is an assembler for a machine with no registers, no stack and no memory except its own program counter. This essay evaluates it, then designs MAXI, a higher level language for composing strategies out of behaviors, and works through functions, arguments, state, compilation, visualisation and testing.

  • ANT is closer to a next-address microcode than to a normal assembler: every instruction names its successors, and the program counter is the ant's only private memory.
  • With no return stack, a MAXI function call is an inlined copy. Tail calls are free. Non-tail calls cost states, and the 10,000-state budget is about seven times what the best 2004 brains used, so copying is affordable.
  • Function arguments are compile-time values. Each distinct argument tuple produces a specialised copy, and the real hidden arguments are the exits a behavior returns through.
  • State does exist, and it lives in the program counter: a variable with k values is k copies of the code where it is live. Reading or writing it costs zero rounds, which makes it the fastest memory the ant has.
  • Testing splits cleanly. Compilers and single behaviors get exact, trace-level tests. Strategies get statistics, because one shared random stream makes every game chaotic.

1ANT is an assembler, and an odd one

A brain is a list of at most 10,000 numbered states. Each state holds one of eight instructions, and every instruction names the state (or the two states) to go to next. There is no fall-through to the next line, no registers, no arithmetic, no indirect jump, and no call or return. Every instruction an ant executes costs one round of the game, and a successful Move also puts the ant to rest for 14 rounds, so a step costs 15 rounds.

That is recognisably machine code: opcodes, operands and branch targets, written as numbers. The closest historical relatives are not x86 or the 6502 but drum-memory machines such as the IBM 650, where each instruction carried the address of its successor, and horizontal microcode, where each micro-instruction holds a next-address field and a branch condition. ANT is a microcode sequencer with ant sensors wired to its condition inputs.

Two more facts shape everything that follows. First, all ants run the same program from state 0, facing east, so any division of labour must be derived from where an ant starts. The Red Team wrote a generator that identified each of the 91 ants in its hill by position so that each could get its own program. Second, an ant cannot read its own direction or rest counter. It can read whether it carries food, through a quirk: the ant itself occupies its cell, so Sense Here FriendWithFood is true exactly when it is carrying food.

Verdict: ANT is an excellent target and a poor source. It is complete for its machine, it is tiny, and its semantics fit on one page. But loops, subroutines, roles and phases are all invisible in it. Writing ANT by hand is writing microcode. Every team that did well wrote a compiler first.

2What the 2004 teams built

The two compilers in our references are the two seeds of MAXI.

Red Team, antc. A C-like language with if, while, goto, labels and && || ! over sense conditions, plus m4 macros for reuse. Their notes say the boolean operators were "greatly beneficial". The macros show where the language ran out. They needed a hand-built label() trick to keep labels unique when a macro was expanded twice, which is the hygiene problem of every textual macro system. They passed code as strings, as in ray_wander_until(`sense here marker 2 || …'), and they passed labels to jump to on failure, as in ray_follow_path(2, 3, `food', `restart_find_food_rmdm2'). That last argument is a continuation, written by hand.

ANTisocial, OCaml combinators. Martin Jambon's library defines a fragment as type f = string -> string -> instr: give it a success label and a failure label, and it produces code. On top of that sit l_and, l_or, l_not, l_while, l_if, l_choose and l_switch. This is continuation-passing style with exactly two continuations. It composes well, and l_not is just swapping the two labels.

MAXI keeps the structured control of antc and the typed, composable fragments of ANTisocial, and generalises the two continuations to any number of named exits.

3MAXI at a glance

MAXI has three kinds of definitions. A condition is a pure boolean expression over senses. A behavior is a piece of control with one entry and a set of named exits. A strategy wires behaviors together by connecting exits to entries, and assigns roles. Everything resolves at compile time into a single ANT file.

MAXI: conditions and behaviors

-- markers are declared by name and type; the compiler allocates bits
marker trail : cycle3   -- directed trail, 3 phases, uses 2 bits
marker guard : flag

cond blocked(d: Dir) =
  sense d Rock or sense d Friend or sense d Foe

cond danger =
     (sense LeftAhead Foe and
        (sense Ahead Foe or sense RightAhead Foe))
  or (sense Ahead Foe and sense RightAhead Foe)

behavior step(d: Dir) exits moved, blocked {
  face d                 -- 0 or 1 Turn, chosen at compile time
  move else exit blocked
  exit moved
}

behavior wander exits found {
  loop {
    if sense Ahead Food { move else continue; exit found }
    choose {
      1: turn left
      1: turn right
      1: move else skip
    }
  }
}

MAXI: a strategy

strategy harvester {
  start forage
  forage   = wander                 [found  -> load]
  load     = pickup                 [ok     -> go_home,
                                     empty  -> forage]
  go_home  = follow(trail, toward: home)
                                    [arrived -> unload,
                                     lost    -> search]
  search   = wander_until(sense Here Home)
                                    [found  -> unload]
  unload   = drop >> forage
}

-- higher order: wrap any behavior with a danger poll
behavior careful(b: Behavior) =
  watch danger do { about_face; move else skip } in b

colony {
  role = start_position()   -- exits: rim, inner, centre
  rim    -> careful(harvester)
  inner  -> careful(harvester)
  centre -> guard_food
}

The syntax is a sketch. The important decisions are underneath it: exits are part of a behavior's type, the compiler checks that every exit is wired somewhere, markers are named and typed rather than numbered, and nothing in the language implies runtime machinery the ant does not have.

4Functions for behaviors and strategies

A function call needs somewhere to keep the return address. On a normal machine that is a stack. An ant has no stack, so the only place a return address can live is the program counter itself. That gives the central rule of MAXI: calling a behavior means making a copy of it, and the copy's state numbers encode where it returns to.

Seen through continuation-passing style this is natural. A behavior is a function from its exits to an entry state, the same idea as ANTisocial's string -> string -> instr, generalised. Calling step(Ahead) with moved → 40 and blocked → 70 produces fresh states whose exit edges point at 40 and 70. Called again with different exits, it produces a different copy.

What a call costs

A behavior of s states called from k non-tail sites costs k·s states. Nesting multiplies: a 40-state behavior called from 5 places inside a behavior that is itself called from 4 places costs 800 states. That would be alarming on a 1 KB machine. Against a 10,000-state budget and winning brains of 400 to 1,400 states it is affordable, and two compiler passes recover much of it: tail calls share, and state minimisation (section 6) merges copies whose remaining behaviour is identical. MAXI should still print a size report per behavior, like a linker map, so the cost of an abstraction is visible.

Recursion, loops and results

Tail recursion is a loop and costs nothing. General recursion would need unbounded copies, so MAXI rejects it, except for recursion on a compile-time integer (spiral(n) = …spiral(n-1)…), which simply unrolls. A behavior returns values through its exits: a behavior that "returns a direction" has six exits (or three, relative to the current heading). An exit is a return value encoded in control flow.

Behaviors versus strategies

The two words name two scales of the same mechanism. A behavior is a local skill of 5 to 100 states: step, follow a trail, lay a trail, pick up, surround an enemy, wait. A strategy is a colony-wide plan: which ants take which role, in which phase, and how behaviors hand over to each other. Strategies are where higher-order functions earn their place, because the useful strategy operators all take behaviors as arguments:

CombinatorMeaningCompiles to
a >> bSequence: run a, then b from its main exit.Wire a's exit to b's entry. No cost.
first(a, b, c)Try each until one succeeds.Each failure exit wired to the next entry, as in l_or.
choose { 2: a; 1: b }Weighted random pick.A chain of Flip: Flip 3 to b, otherwise a.
watch c do h in bPreempt b with handler h when c holds.A poll of c inserted at every loop head (or before every Move) of b. Costs rounds, not just states.

roles { … }Branch by starting position.A start-up classifier whose exits enter different strategies.

watch deserves a remark. The ant has no interrupts, so a subsumption architecture (Brooks's layered behaviors, where "flee" overrides "forage") must be compiled into polling. That is a program transformation, a kind of aspect weaving, and it makes the cost of vigilance explicit: each poll is a Sense, and each Sense is a round.

5Multiple arguments, without state

Since a call is a copy, an argument is whatever makes copies differ. All MAXI arguments are compile-time values, and a call with a new combination of arguments produces a new specialised copy. This is monomorphisation, the way C++ templates or Rust generics work, and it is also partial evaluation: the compiler runs the parts of the program that depend only on the arguments and leaves the rest as ANT.

Multiple arguments therefore cost nothing at runtime. follow(trail, toward: home) and follow(trail, toward: food) are two copies with different marker tests baked in. Currying works too: follow(trail) is a behavior-valued expression waiting for its second argument, and only the fully applied forms that are actually used produce code. The size cost is the number of distinct tuples used, not the product of the domains.

When the argument is only known at runtime

Sometimes a value is genuinely dynamic: "go back the way I came", "follow whichever trail phase is under me". MAXI handles this the way partial evaluators do, by enumerating the possible values and branching into one specialised copy per value. A match on a sensed value becomes a Sense chain whose leaves are the specialisations:

MAXI

-- phase is read from the cell, then fixed per branch
match trail.here {
  p0 -> follow_from(p0)
  p1 -> follow_from(p1)
  p2 -> follow_from(p2)
  none -> exit lost
}
-- shorthand for the same thing:
with p = trail.here in follow_from(p)

ANT, with cycle3 on markers 0 and 1

; phase encoding: p0=01, p1=10, p2=11, none=00
Sense Here 1 2 Marker 0  ; 0
Sense Here 3 4 Marker 1  ; 1: bit0 set
Sense Here 5 6 Marker 1  ; 2: bit0 clear
; 3 -> follow_from(p2) copy
; 4 -> follow_from(p0) copy
; 5 -> follow_from(p1) copy
; 6 -> lost

Note that the value never sits anywhere. After two senses the ant is simply in a different copy, and the copy is the value. That is the bridge to the next section: once an argument has been dispatched, it has become state carried by the program counter.

One more channel exists: a marker in the cell. An ant can write a value and read it back while it stays put, and any ant that walks over that cell later can read it too. That is not argument passing but communication, and MAXI treats it as such (section 7).

6Static compilation

MAXI is compiled entirely ahead of time to one ANT file. There is no runtime system, because there is nowhere to put one. The pipeline:

Parse and resolveNames, imports, marker declarations.
CheckTypes, exhaustive exit wiring, marker bit allocation, bounded recursion.
ExpandInline and specialise every call; build a graph of primitive nodes plus virtual goto nodes.
OptimiseJump threading, fact propagation, algebraic rewrites, dead states, minimisation.
EmitNumber states (entry = 0), write .ant and a source map.

Things specific to this machine

No jumps. ANT has no goto, so every virtual goto node must be threaded away by pointing its predecessors at its target. A loop that contains no real instruction, such as loop {}, has nothing to thread to. The compiler must reject it or insert a deliberate one-round pause such as Sense Here Home with both targets equal.

Algebraic laws that save rounds. Move fails exactly when the cell ahead is rock or holds an ant, which is exactly blocked(Ahead). So the compiler may delete a blocked(Ahead) test that leads to the same place as a failing Move. Hand-written ants often test first, then move, and pay up to three extra rounds per step for no information:

Naive: test, then move (up to 4 rounds before the step)

Sense Ahead 99 11 Rock     ; 10
Sense Ahead 99 12 Friend   ; 11
Sense Ahead 99 13 Foe      ; 12
Move 40 99                 ; 13  moved -> 40, blocked -> 99

After the rewrite (1 round)

Move 40 99                 ; 10  same exits

The rewrite only applies when the blocked exit has nothing else to do. If the test guards a Turn (as in step(RightAhead)), the test is what avoids turning for nothing, and it stays.

Which facts survive between instructions. Other ants act between any two of your instructions, so a sensed fact may be stale one round later. A compiler that wants to fold repeated tests has to know which facts are stable. The rules fall out of the spec neatly:

FactStable untilWhy
Rock, Home, FoeHome anywhereyou Turn or Move (the sensed cell changes)Terrain never changes.
Marker i and Food Hereyou Move, or change them yourselfOnly the ant in a cell can mark it or pick up from it, and only one ant fits in a cell.
Carrying food (Here FriendWithFood)you PickUp or DropIt is your own has_food.
Friend, Foe, Food, Marker Aheadthe next roundOther ants move, mark and pick up between your instructions.

A useful consequence: a MAXI condition such as a and b and c is not atomic. It takes up to three rounds, and the world can change while it is evaluated. The language should say so plainly, and the compiler should order the terms by cost and likelihood, cheapest and most decisive first. Simulation statistics can supply the likelihoods, which makes this a profile-guided optimisation.

Minimisation. Inlining produces many copies whose remaining behaviour is identical: same instruction, same operands, equivalent successors. Partition refinement (Hopcroft's algorithm, or bisimulation on the labelled graph) merges them. This is the pass that makes cloning cheap in practice, and it is safe because two states with the same future are interchangeable.

Timing analysis. Each behavior gets a best and worst case in rounds per iteration, counting 15 for a successful move. "This patrol loop polls for danger every 17 rounds at worst" is the kind of number a strategy designer needs and cannot get from the ANT listing.

Budget and determinism. The compiler fails if the result exceeds 10,000 states, and reports states per behavior. Output is deterministic for a given source, so diffs of .ant files stay meaningful in git.

7State

It is tempting to say ants are stateless and MAXI should be too. That is wrong. An ant has plenty of state; it is just stored in unusual places.

How the current instruction carries state

Every state number answers two questions at once: "what do I do next?" and "what do I know?". After Sense Ahead 12 30 Food, an ant in state 12 knows there was food ahead and an ant in state 30 knows there was not. Nothing was stored, yet the knowledge persists for as long as the ant stays in that region of code. A program that needs to remember one extra bit through a stretch of code needs two copies of that stretch. A variable with k values is k copies where it is live.

This memory has a remarkable property: reads and writes cost zero rounds. A read is resolved at compile time (each copy already knows the value), and a write is folded into the next instruction's target. Compare a marker, which costs a round per bit to read and can only be written in the current cell. The program counter is the fastest and most private memory an ant has. Its only cost is code size.

MAXI variables are sugar for duplication

So the question is not whether MAXI can have state, but how much. MAXI allows variables with small finite domains and compiles them by product construction: the code where the variable is live is copied once per value, assignments become jumps between copies, and reads disappear. Liveness analysis keeps the copies local.

MAXI

behavior explore exits found {
  var heading : Dir6 = static  -- tracked by the compiler
  var streak  : 0..3 = 0
  loop {
    if sense Ahead Food { exit found }
    move else { turn right; streak = 0; continue }
    streak = streak + 1
    if streak == 3 { turn left; streak = 0 }
  }
}

A 10-state body with full dead reckoning needs 9,610 states, which is nearly the whole budget. Small counters are cheap; coordinates are not.

Tracking heading statically is worth singling out. The ant cannot sense its direction, but the compiler knows every Turn, so in code where the heading is tracked MAXI can offer absolute directions ("face east") and compile them to the right number of turns. It costs six copies of that region and zero rounds.

When to replace state with conditions

Every piece of state has two cheaper-looking alternatives, and a good MAXI program picks per case:

  1. Re-sense instead of remembering. "Am I carrying food?" is Sense Here FriendWithFood; "am I home?" is Sense Here Home. This trades a round for a halving of code. It is the right choice when the fact is cheap to sense and rarely needed.
  2. Duplicate code instead of storing. Write the two cases as two behaviors and wire them separately. This is the same thing as a variable, done by hand, and it is the native form of state on this machine. It is not a hack.
  3. Write it into the world. Markers are memory that outlives the ant's path and that other ants can read: the Red Team's three-phase directed trails and concentric hexagons around the hill, ANTisocial's 3-bit counter, guard marks around food. Use markers for anything another ant must know.

The resulting rule of thumb: prefer facts the compiler already knows, then cheap stable senses, then small program-counter variables with short live ranges, and use markers for shared or long-lived information.

Markers as a typed heap

Six bits per cell is a register file, and allocating it is a register allocation problem. MAXI declares markers by name and type (flag, cycle3, counter(3), enum{…}), and the compiler assigns bit numbers, rejects programs that need more than six bits, and generates the increment and decode logic, such as the cyclic phase arithmetic for trails. Two behaviors that both quietly use marker 2 for different purposes is exactly the bug this prevents.

8Seeing the program

A raw state graph does not help. ANTisocial's own graph of its 409-state brain is a hairball, and the Red Team's 1,386 states would be worse. Humans need the program shown at the level they wrote it, and they need the running simulation tied back to that level. Three views, from coarse to fine:

1. Strategy as a statechart

Nodes are behaviors, edges are exits, labelled with the exit name. Roles and phases are nested regions, in the style of Harel statecharts. This is the view for discussing a plan.

2. Behavior as a box with ports

Inside a behavior, a flowchart: diamonds for senses, rectangles for actions, and exits drawn as named ports on the box edge. Each node can show its cost in rounds. Because exits are ports, a behavior box can be dropped into a strategy diagram like a component on a circuit board.

3. The running colony, mapped back to source

The compiler should emit a source map next to the .ant file: for each state, the source span and the behavior path that produced it. With that, the Ambiant Arena simulator can show what a human actually wants to know:

  • colour each ant by its current behavior instead of by team only;
  • on hover, the behavior path, e.g. colony › rim › careful › harvester › go_home › follow › step;
  • a stacked chart of how many ants are in each behavior over time, which shows phases and stalls at a glance;
  • a timeline for one selected ant, a strip of behavior names across rounds;
  • marker overlays by declared name (trail, guard) rather than by bit number, with cyclic trails drawn as arrows.

9Testing: exact or statistical

A game is fully deterministic given the world, the two brains and the random seed. But there is a catch that decides the whole testing strategy: all ants share one random number stream, consumed in ant-id order every round. If one ant executes one more or one fewer Flip, every later draw for every ant shifts. A one-line change anywhere produces a completely different game after a few hundred rounds. Exact traces are therefore excellent for testing tools and small behaviors, and nearly useless for judging strategies.

Statistics for strategies

The contest scored by food in the anthill after 100,000 rounds on random 100×100 worlds, with each pair of brains playing both colours. A strategy test should mirror that:

  • Paired design. Run A and B on the same worlds, same seeds and same colours against the same opponent pool. Pairing removes the variance due to world layout, which is large.
  • Report intervals, not single numbers. Win rate with a Wilson interval; food margin as a mean with a confidence interval. To see a 5-point change in win rate at 95% confidence takes roughly 1.96² × 0.25 / 0.05² ≈ 384 games, so a quick check of 20 games can only reveal large differences.
  • Stop early when the answer is clear. A sequential probability ratio test lets a tournament stop once B is clearly better or clearly not.
  • Rank many versions together. An Elo or Bradley–Terry rating over a league, as the Red Team did informally with their overnight tournament, guards against non-transitive results (A beats B, B beats C, C beats A), which are common with strategies such as traps.
  • Fixed seeds in CI, fresh seeds overnight. Fixed seeds keep the quick suite reproducible; fresh seeds keep it honest.

Cost is the constraint. A full game is 100,000 rounds for about 180 ants, around 18 million ant steps. Statistical suites need a fast headless simulator, and should use shorter games and smaller worlds for behavior-level questions, keeping full games for strategy decisions.

10Where to start

  1. A combinator core in JavaScript, next to the existing simulator: behaviors as functions from exit labels to graph fragments, in the ANTisocial style, with named exits. This is MAXI's intermediate representation, and useful on its own.
  2. The optimiser and emitter: jump threading, the Move rewrite, minimisation, size report, source map.
  3. Source maps in Ambiant Arena: ants coloured by behavior, behavior path on hover, behavior population chart.
  4. A headless tournament runner with paired games and intervals.
  5. MAXI surface syntax last, once the core has shown which constructs pay for themselves.
